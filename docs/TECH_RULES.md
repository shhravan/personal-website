# Technical rules

Keep it simple: a site that is easy to read, explain and maintain.

## Stack
- **Plain HTML, CSS and JavaScript.** No frameworks, packages or build step.
- **Python sync script** (`scripts/substack_sync.py`, standard library only), run by a GitHub Action once a month and on demand:
  - copies the free posts from shrvvn.substack.com into `blog/<slug>/index.html` and the list in `blog/index.html`
  - Substack's JSON API first, the RSS feed as a fallback; HTML cleaned to an allowlist; images downloaded into `images/blog/`
  - retries on HTTP 429/503 (honoring `Retry-After`, capped), and the job has a 20-minute timeout
  - each run re-enables its own workflow through GitHub's API (`actions: write`), because GitHub switches off scheduled jobs in public repos after 60 days without activity
  - `--limit N` fetches only the newest N posts, for testing against a big publication (`python3 scripts/substack_sync.py --source https://example.substack.com --limit 4`)
  - Substack blocks GitHub's runners, so requests go through a Cloudflare Worker relay (`worker/feed-relay.js`) with a fixed allowlist and a secret key (`X-Relay-Key`; GitHub secret `SUBSTACK_RELAY_KEY`, Worker secret `RELAY_KEY`, address in the GitHub variable `SUBSTACK_RELAY_URL`)
- **Hosting:** GitHub Pages from `main`, at `shravanlad.com` (the `CNAME` file; DNS at Spaceship: four A records to GitHub Pages and a `www` CNAME to `shhravan.github.io`).
- **Staging:** Cloudflare Pages deploys the working branch (`claude/personal-website-workflow-pjo7rz`) to `staging.shravanlad.com`, plus a preview link per pull request. `_headers` marks staging `noindex` (GitHub Pages ignores that file). Check changes there before merging to `main`.
- **Fonts:** Google Fonts.
- **Music:** self-hosted MP3s in `audio/`, played with the browser's built-in audio player. Keep files at 128 kbps or less with tags stripped (`ffmpeg -map_metadata -1`).

## Folder layout
```
index.html          home page
work/ projects/ blog/ photography/ rabbit-hole/   one folder per page, each with index.html
styles.css          one shared stylesheet
theme.js            theme switch, record player, in-place page swaps (in every page's <head>)
script.js           hero rotation and email links; re-runs on each page swap
field.js            letter field and shoreline (WebGL)
images/             hero/, covers/, logos/, blog/
audio/              the record player's songs (NAME.mp3, named after the cover)
scripts/            Substack sync
worker/             Cloudflare Worker relay
tests/              automated tests
docs/               product, design, technical and security docs
```

## Rules
1. One change per branch and pull request; never push to `main` directly.
2. **Relative links** (`../work/`, not `/work/`) so pages work at any address.
3. Mobile first: every page must look right on a phone.
4. Images: compressed (about 200–400 KB max), with `alt` text, metadata stripped. Hero photos come in two WebP sizes, `NAME.webp` (1200px) and `NAME-700.webp` (phones), framed with the `FOCUS` list in `script.js`. File names are short, lowercase and descriptive.
5. Blog pages are generated by the sync script; never edit them by hand. Each post has a canonical link to Substack.
6. No secrets in the repo. Credentials live only in GitHub Actions secrets and Cloudflare Worker secrets.
7. Every page carries the Content-Security-Policy meta tag; a new outside service must be added to it on every page (see `SECURITY_RUNBOOK.md`).
8. When CSS or JS changes, bump the `?v=` number on its links in every page.
9. Every page copies the home page skeleton (`<a class="logo">`, `<main class="col ...">`, the `.foot` line, scripts at the end). Page swaps replace only `.logo` and `<main>`, so page code sets itself up again on the `page:load` event.
10. Tests (`tests/`, standard library `unittest`, no network) run on every push. Run `python3 -m unittest discover -s tests -v` before opening a PR; the Substack sync refuses to publish if they fail.
11. Comments explain *why*, in plain English.
12. Keep the docs current in the same PR as the change.
